先了解一下什么事UDF提权：

UDF 的全称是 User Defined Function（用户自定义函数）。

MySQL 作为一个数据库，本身自带了很多功能函数，比如 md5()、concat()、version()。但是，总有些开发者觉得不够用，于是 MySQL 的设计者就留了一个“后门”： 允许开发者用 C 语言或者 C++ 自己写一段代码，编译成动态链接库（Windows 下是 .dll，Linux 下是 .so），然后加载进 MySQL 里，当成 MySQL 自带的内置函数来用。

这个机制的本意是为了方便扩展功能，比如有人想在数据库里直接做一个超复杂的财务计算，就可以写个 UDF。

就比如我们想要执行ls等操作，如果我们可以利用UDF去写入，那么我们就可以实现执行ls等命令

也就是说我们是利用这个机制把我们的东西塞到mysql数据库里面，而这个机制只有例如root身份等才可以使用，其他细致的原理这里就不赘述了

那么什么是udf提权呢？

如果 MySQL 服务在启动时，是以系统的最高权限（root 账户）运行的，那么你通过 UDF 执行的任何系统命令，也全部是 root 权限！

你原本只是一个利用网页漏洞（比如你刚才做的那个 ?id=1）进来的卑微 Web 用户（通常是 www-data），现在却利用 MySQL 的 UDF 功能，瞬间摇身一变成为了操作系统的“神”。这就叫提权（Privilege Escalation）。

能够执行提权的前置条件非常苛刻

  1. 当前用户已经拿到 MySQL 的权限（通常是 root）
  2. MySQL 进程运行权限较高（如 root）
  3. 有 文件写入权限（plugin_dir 目录）
  4. 可以使用 CREATE FUNCTION 创建函数（有 CREATE 权限）
  5. secure_file_priv是空

这道题我们先通过命令来查看我们登录mysql时是否是root用户：

  • sqlmap -u “http://node1.anna.nssctf.cn:28725/?id=1“ –random-agent –is-dba

  • --is-dba (核心目的：查户口)

    • 作用：DBA 是 Database Administrator（数据库管理员）的缩写。这个参数会让 sqlmap 在确认存在注入后，立刻去查一下当前连接数据库的账号是不是最高权限（比如 MySQL 里的 root）。

  • 当然这里前面还有个–random-agent，这个命令就是为了防止有些mysql库看见你是sqlmap来的直接给你ban了，所以加一个这个之后sqlmap会伪装成正常的浏览来的

这个命令如果返回了true，那么就说明我们这里是root用户

那这里就可以执行了

在这里要熟悉sqlmap的操作：

当然这里要用的命令上图是没有的

我们得知了我们是root之后，那我们句执行udf操作，如果手动操作就太复杂了，这里还是借用了sqlmap

sqlmap -u “http://node1.anna.nssctf.cn:28725/?id=1“ –random-agent –os-shell

--os-shell (终极杀招：获取系统命令行)

  • 作用：尝试在目标数据库所在的服务器上，弹出一个交互式的操作系统命令行（Shell）。
  • 底层逻辑（呼应我们刚刚讲过的知识）： 当 sqlmap 发现存在注入漏洞时，它会立刻尝试两条路线来拿权限：
    1. 写木马路线：如果它能猜到网站的绝对路径（比如 /var/www/html/），并且数据库有写文件权限，它会用 SQL 语句写一个 PHP 一句话木马进去，然后通过这个木马帮你执行系统命令。
    2. UDF 提权路线：就像我们刚才聊的，如果写木马行不通，它就会尝试往 MySQL 的插件目录里塞一个 .so 动态链接库，创建一个自定义函数，利用数据库的底层机制直接执行系统命令

然后我们就可以实现随便的命令执行了
