简介

我们在学习渗透测试甚至在打CTF的过程中都可能在遇见linux提权的情况 个人感觉这部分的内容在考到了之后更多的是靠自己的积累吧 毕竟这部分的内容有好多cve的东西 如果自己遇见了现场去推感觉效率也不高

再linux提权当中 主要分为内核提权和其他提权 那么内核又是什么呢？

其实内核是一个特殊的c语言程序 它拥有直接操控内存的权限 我们所熟知的root在运行时也需要经过内核的同意

内核有四个核心子系统：

1.内存管理

在内存管理下 内核可以执行分配与回收 当我们在运行脚本时 需要内存来存放变量 但是由于安全限制我们不能直接去请求一个内存来执行 而是必须向内核申请 内核负责分配内存

另外内核还负责分发虚拟内存 让每个程序以为自己独占整个系统的内存 提高运行效率 内核又将这些虚拟内存映射到真实的物理内存上

内核还负责执行安全隔离，也就是一个程序无法读取到另一个程序的内存 除非我们单独进行设置 提权漏洞往往就出现这里 如果内核在做内存映射时出现bug 那么普通用户就可能读到root的内存区域

2.进程与cpu调度

这部分其实对于提权来说不是特别重要 这里就简要讲解一下 我们都知道电脑同时可能运行着成百上千的进程 那么这时就需要内核来进行进程分配

3.设备驱动与硬件交互

内核可以处理各种不同硬件的信号指令 比如键盘 显卡 网卡等 内核负责统一翻译为对应硬件听得懂的语言

4.虚拟文件系统与权限控制

再linux当中 不管是硬盘文字还是网络套戒子甚至硬盘设备 再linux中都表现为文件 内核维护着巨大的文件系统树 并在每一次程序尝试打开 读取写入文件时 进行严格的权限校验（核对uid和gid 这两个概念在后面细说)

suid提权

suid全称是Set owner User ID up on execution。这是Linux给可执行文件的一个属性，上述情况下，普通用户之所以也可以使用ping命令，原因就在我们给ping这个可执行文件设置了suid权限。

在linux当中 在运行时会有三个id项：

· Real uid 执行该进程的用户实际的UID

· Effective uid 程序实际操作时生效的UID（比如写入文件时，系统会检查这个UID是否有权限）

· Saved uid 在高权限用户降权后，保留的其原本UID（本文中不对这个UID进行深入探讨）

再通常情况下Effective id和Real id是相等的 所以只有uid=0才可以写入/etc/passwd 有suid的程序启动时 Effective uid就等于二进制文件的所有者 此时两个就会不相同 正常情况下 linux其实都是只检查euid

就比如ping命令就是典型的两个不一样 因为这个命令需要调用底层网卡 而linux规定只有uid=0也就是root用户才能执行 我们不可能让所有想要执行ping命令的用户都是root那么这时候就想出了一种方法 那就是给/bin/ping这个程序加了一个魔法属性–suid也就是s位

ls -al /bin/ping 的结果是-rwsr-xr-x

这里先来对命令和结果进行一个复习：

ls不说了 -a就是列出全部 -l就是指以长格式输出 加了这个参数之后系统就会把文件权限 拥有者 大小修改时间等内容全部都列出来

-rwsr-xr-x 到底代表什么？

这串字符一共 10 位，它是 Linux 系统的“权限密码本”。我们把它像切香肠一样切开来看：

[ - ] [ r w s ] [ r - x ] [ r - x ]

看长相（第 1 位）

  • -：代表这是一个普通文件（如果是 d 就是目录 Directory，如果是 l 就是快捷方式 Link）。

看主人（第 2 到 4 位） -> r w s

这三位代表文件拥有者（Owner，在这里是 root）对这个文件的权限：

  • r (Read)：可以读。
  • w (Write)：可以修改/写。
  • s (SUID)：高能预警！ 这里本来应该是 x（可执行），但它变成了 s。这就代表被施加了上文提到的“魔法隐身衣”（SUID）。任何执行它的人，执行期间都会拥有主人的权限。

看自己人（第 5 到 7 位） -> r - x

这三位代表文件所在用户组（Group）的权限：

  • r：可以读。
  • -：本来应该是 w 的地方是横杠，代表没有写入权限。
  • x (eXecute)：可以执行/运行。

看外人（第 8 到 10 位） -> r - x

这三位代表其他所有人（Others，也就是作为普通用户的你）的权限：

  • r：可以读。
  • -：没有写入权限（你改不了 ping 的代码）。
  • x：可以执行（你可以敲回车运行它）。

上述的s属性就意味着 不管谁来运行这个程序 只要程序跑起来运行着的euid就会变成这个程序拥有者的uid

当然也不是有s位也就是suid选项的程序都可以提权 首先这个程序的拥有者必须是root 否则最多执行一个水平越权

还有个条件就是这个程序是允许你自由执行的 我们总不能指望ping命令来反弹root shell吧

我们挑最典型的来解释一下里面的参数：

  • find /：从系统根目录 / 开始，翻遍整个硬盘。
  • -user root：只找拥有者是 root 的文件（确保魔法衣的主人是老大）。

cve-2021-4034

做题的时候遇见了一种非常难受的情况，那就是虽然我可以看见各级目录的文件名但是当我想要使用cat或者一些其他命令进行进一步操作时，就会提示我们没有权限，这个时候我们就肯定需要提权操作了

这里要大致进行叙述的就是cve-2021-4034漏洞，这个漏洞存在了数年，在近些年才被扒出来，那么这个漏洞究竟是什么？

当然以下只做一个简单的描述，详细的原理就自行上网查询了

这里要大致介绍以下argc和argv，当我们在linux运行一个程序时，系统会传给它两个核心数组

  1. argv[]：参数数组（比如 ls -l，argv[0] 是 ls，argv[1] 是 -l）。
  2. envp[]：环境变量数组（比如 PATH=/usr/bin）。

在内存里，这两个数组是紧挨着存放的。

正常情况下说，argv默认是文件名本身，比如test.php，那么argc，也就是参数个数至少都是1

我们需要知道polkit 是一个应用程序级别的工具集，通过定义和审核权限规则，实现不同优先级进程间的通讯：控制决策集中在统一的框架之中，决定低优先级进程是否有权访问高优先级进程。

而我们这个漏洞正是利用的是polkit里面的pkexec，pkexec 的源码里有一段逻辑，大意是：“我要看看用户传了什么参数，如果没有路径，我就去 PATH 环境变量里找”。那么我们这个时候就可以进行操作了

我们通过特殊的手段，传一个空的argv过去，那么这个时候argc就变成0了，而pkexec的代码决定了它是从argv[1]开始找的，但是这里根本就不存在argv[1]，那这个时候pkexec就会顺势往后进行读取,而上面我们说了argv[]和env是紧挨在一起的那么这个时候pkexec就会读取envp[0]了，我们就利用这个envp[0]来进行我们最终的提权操作

以上就是这个漏洞的一个大致原理

1️⃣ echo "..." （打包发货）

  • 作用： echo 命令的作用是在终端里打印一段文本。这里它把那一长串看似乱码的 Base64 字符串当作文本输出了出来。

2️⃣ | （管道符：传送带）

  • 作用： 这是 Linux 里极其伟大的发明。它像一条传送带，把左边 echo 吐出来的那一长串字符串，直接“喂”给右边的命令，而不是显示在屏幕上。

3️⃣ base64 -d （核心解码器）

  • 作用： base64 是 Linux 系统自带的编解码工具。后面的 -d 参数是 decode（解码）的缩写。
  • 它接收了管道传过来的那一长串代码，瞬间把它还原成了咱们上一回合讲的那段真正的 C 语言源码。

4️⃣ > /tmp/exp2.c （落地写盘）

  • 作用： > 是重定向符号，意思是“把前面解码出来的 C 语言代码，不要打印在屏幕上，而是写进一个文件里”。
  • 为什么选 /tmp 目录？（实战重点）： 在 Linux 系统中，你当前的身份是极其卑微的 www-data，你在这个系统的绝大多数地方都没有写文件的权限。但是，/tmp（临时文件夹）是 Linux 里唯一一个默认允许所有人（任何人）读写的地方。所以这里是存放咱们黑客武器的完美阵地！

情况 A：弹回交互式 Root Shell

** 判断方法：**

  1. 靶机出网（能连通你的 Kali 或 Yakit）。
  2. 你已经有了一个相对稳定的通道（比如你已经通过 Yakit 弹了一个低权限的 Shell 回来）。

当然这个方法就需要考虑tty了，下面的b和c是不需要考虑tty的，蚁剑是没有原生tty的，它是一个伪终端，也就是pty，它和原生tty的区别就是原生tty由系统内核直接管理，具有完整的终端口特性；

而蚁剑的pty则是Web 层模拟，依赖目标语言（PHP/ASP/JSP）的执行能力，某些极端场景（如复杂信号、内核级操作）可能不如原生稳定，但日常命令、提权、运维足够用。

那为什么使用方法a就需要我们具有tty环境呢？

  • 原理解析： Payload A 的最后一句是 execve("/bin/sh", ...)。它的目的是在当前进程中“召唤”出一个一直运行的 Shell，等待你不断输入 ls、whoami 等命令。
  • 翻车现场： 如果你在蚁剑（没有 TTY）里执行 Payload A，蚁剑底层的 PHP 会帮你执行程序，程序确实召唤出了 /bin/sh 并且变成了 Root 权限，但是！这个 Root Shell 找不到可以输出画面的屏幕，也找不到可以接收你打字的键盘。 结果就是：网页一直转圈圈卡死，或者程序瞬间崩溃退出，你什么都看不到。

我们可以输入gcc –version或者gcc -v来查看版本信息，或者我们可以输入command -v gcc，如果环境存在gcc那我们就可以看见一个文件路径，反之不存在那么我们就看不见文件路径
