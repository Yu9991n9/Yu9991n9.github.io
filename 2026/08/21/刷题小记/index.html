先了解一下什么事UDF提权：

UDF 的全称是 User Defined Function（用户自定义函数）。

MySQL 作为一个数据库，本身自带了很多功能函数，比如 md5()、concat()、version()。但是，总有些开发者觉得不够用，于是 MySQL 的设计者就留了一个“后门”： 允许开发者用 C 语言或者 C++ 自己写一段代码，编译成动态链接库（Windows 下是 .dll，Linux 下是 .so），然后加载进 MySQL 里，当成 MySQL 自带的内置函数来用。

这个机制的本意是为了方便扩展功能，比如有人想在数据库里直接做一个超复杂的财务计算，就可以写个 UDF。

就比如我们想要执行ls等操作，如果我们可以利用UDF去写入，那么我们就可以实现执行ls等命令

也就是说我们是利用这个机制把我们的东西塞到mysql数据库里面，而这个机制只有例如root身份等才可以使用，其他细致的原理这里就不赘述了

那么什么是udf提权呢？

如果 MySQL 服务在启动时，是以系统的最高权限（root 账户）运行的，那么你通过 UDF 执行的任何系统命令，也全部是 root 权限！

你原本只是一个利用网页漏洞（比如你刚才做的那个 ?id=1）进来的卑微 Web 用户（通常是 www-data），现在却利用 MySQL 的 UDF 功能，瞬间摇身一变成为了操作系统的“神”。这就叫提权（Privilege Escalation）。

能够执行提权的前置条件非常苛刻

  1. 当前用户已经拿到 MySQL 的权限（通常是 root）
  2. MySQL 进程运行权限较高（如 root）
  3. 有 文件写入权限（plugin_dir 目录）
  4. 可以使用 CREATE FUNCTION 创建函数（有 CREATE 权限）
  5. secure_file_priv是空

这道题我们先通过命令来查看我们登录mysql时是否是root用户：

  • 当然这里前面还有个–random-agent，这个命令就是为了防止有些mysql库看见你是sqlmap来的直接给你ban了，所以加一个这个之后sqlmap会伪装成正常的浏览来的

这个命令如果返回了true，那么就说明我们这里是root用户

--os-shell (终极杀招：获取系统命令行)

  • 作用：尝试在目标数据库所在的服务器上，弹出一个交互式的操作系统命令行（Shell）。
  • 底层逻辑（呼应我们刚刚讲过的知识）： 当 sqlmap 发现存在注入漏洞时，它会立刻尝试两条路线来拿权限：
    1. 写木马路线：如果它能猜到网站的绝对路径（比如 /var/www/html/），并且数据库有写文件权限，它会用 SQL 语句写一个 PHP 一句话木马进去，然后通过这个木马帮你执行系统命令。
    2. UDF 提权路线：就像我们刚才聊的，如果写木马行不通，它就会尝试往 MySQL 的插件目录里塞一个 .so 动态链接库，创建一个自定义函数，利用数据库的底层机制直接执行系统命令

代码解析:

步骤 操作

1 接收上传文件

2 将文件保存到 /etc/时间戳.原文件名

3 用 unzip 命令解压该文件到 /etc/ 目录

4 删除原上传的 zip 文件

5 输出 “ghz”

需要注意的是，这里解压的路径是/etc而非/var/www/html，所以我们传入一句话木马的话连接不上，我们需要先积极性软连接

第一句：ln -s /var/www/html hacker_dir

这句话的作用是**“造一座任意门（快捷方式）”**。

  • ln：这是 Linux 里的 link（链接）命令。它的本职工作是把两个文件或目录关联起来。
  • -s：这是最核心的参数，代表 symbolic（符号/软链接）。加了它，你创建的就是一个“快捷方式”。如果不加，创建的就是“硬链接”（相当于克隆实体），那就达不到我们的攻击目的了。
  • /var/www/html：这是目标地址。在绝大多数 Linux 网站服务器（比如 Apache 或 Nginx）里，网页代码默认都存放在这个目录下。我们让任意门的出口对准这里。
  • hacker_dir：这是你给这个任意门起的名字。

第二句：zip -y step1.zip hacker_dir

这句话的作用是**“把任意门打包，准备空投”**。

  • zip：这是 Linux 下极其常用的压缩命令。
  • -y：这是这道题能做成功的绝对灵魂参数！（英文全称是 --symlinks）。
    • 如果不加 -y 会怎样？ zip 命令会极其“老实”。它看到 hacker_dir 是个通向网站根目录的门，它就会直接推门走进去，把网站里的所有网页、图片、数据库配置全都打包进压缩包里。这不仅包变得巨大，而且毫无攻击效果。
    • 加了 -y 会怎样？ zip 命令会变得“表面化”。它不会推门进去，而是直接把这扇“门”（快捷方式）连门框一起打包进压缩包里。
  • step1.zip：这是你打包后生成的压缩包文件的名字，就是我们要传给靶机的那个炸弹。
  • hacker_dir：这是你要打包的目标（也就是咱们刚建好的那个门）。

然后我们把step1.zip上传上去

之后我们要回到kali把hacker_dir给删除，

🚪 第一步的回顾：你建了一扇门

在 step1.zip 里，你传上去了一个叫 hacker_dir 的软链接（传送门）。 服务器把它解压在 /etc/ 目录下。 现在，服务器的 /etc/ 目录下，死死地钉着一扇门，门牌号叫 /etc/hacker_dir，而门背后直通网站根目录 /var/www/html。

📦 为什么第二步必须是同名文件夹？

当你制作第二个压缩包 step2.zip 时，如果你在里面建了一个同名的真实文件夹 hacker_dir，并把木马 shell.php 放在里面。这个压缩包内部的文件路径结构就是： hacker_dir/shell.php

重点来了！想象一下服务器执行 unzip -o step2.zip -d /etc/ 时的“心理活动”：

  1. 快递员（unzip 命令）拆开 step2.zip，看到里面有一个文件叫 shell.php，要求放在 hacker_dir 这个文件夹里。
  2. 快递员看了看收货地址是 /etc/，于是他拼凑出了最终的目的地：“我要把 shell.php 送到 /etc/hacker_dir/ 里面去。”
  3. 快递员跑到 /etc/ 目录一看，“咦？这里正好有一个叫 hacker_dir 的东西存在啊！”（这就是你第一步建的那个软链接）。
  4. 绝大多数旧版的 unzip 命令非常傻，它不会去检查这个 hacker_dir 到底是个真文件夹还是个快捷方式。它只会直接推门走进去！
  5. 结果，快递员一脚跨进了你设好的传送门，把木马 shell.php 吧唧一下扔在了传送门的终点：/var/www/html/shell.php！

木马成功降落到网站根目录，攻击完成！

raw_output 的意思是“输出原始二进制格式”。它的默认值是 false（也就是上面那种安全的 32 位字符串）。 如果一旦把它设置成 true，PHP 就会做一件极其粗暴的事情：

它会把刚才那 32 个安全的字母数字，每 2 个切成一组，然后强行把它们转换成键盘上的符号

大致的流程就是程序会先对字符串进行md5加密，加密之后两个两个分组并且对照ascii表转换为键盘上的字符

面对这种md5参数设置为了true的情况我们一般都是用以下进行绕过：

第一步：普通的 MD5 加密 它先在内部算出了 32 位的安全字符串：276f722736c95d99e9...

第二步：因为有了 true，PHP 开始强行切割 它把上面的字符串每两位切开：27、6f、72、27、36、c9…

第三步：对照 ASCII 码表，强行变身 PHP 会拿着这些两位数的代码，去查电脑底层的字符表（ASCII 码表），把它们变成对应的符号：

  • 查表：27 对应的符号是 ->' (单引号)
  • 查表：6f 对应的符号是 -> o
  • 查表：72 对应的符号是 -> r
  • 查表：27 对应的符号是 -> ' (单引号)
  • 查表：36 对应的符号是 -> 6
  • 查表：c9 对应的符号是 -> [电脑无法显示的乱码]

最终结果： 当你写下 md5('ffifdyop', true) 的时候，这个函数吐出来的内容，不再是刚才那长串安全的字母数字了，而是变成了： 'or'6[一堆乱码]
