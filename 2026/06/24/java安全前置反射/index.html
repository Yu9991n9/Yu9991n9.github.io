访问字段

对任意的一个Object实例，只要我们获取了它的Class，就可以获取它的一切信息。

我们先看看如何通过Class实例获取字段信息，字段其实我们可以理解为我们所常说变量就好

Class类提供了以下几个方法来获取字段：

  • Field getField(name)：根据字段名获取某个public的field（包括父类）这个方法只能拿到public的字段
  • Field getDeclaredField(name)：根据字段名获取当前类的某个field（不包括父类）这个方法就是不管public还是private都可以拿了 但是这个只能拿到当前类的 并不会去到父类里面寻找
  • Field[] getFields()：获取所有public的field（包括父类）把自己和父类的所有public全部拿到并且存到数组里面
  • Field[] getDeclaredFields()：获取当前类的所有field（不包括父类）把自己的所有变量全部拿到并且存到数组里面

修饰符 控制第几盏灯（二进制位） 对应的十进制数字 大白话解释
public 0000 0000 0000 0001 (第 1 位) 1 公开开关
private 0000 0000 0000 0010 (第 2 位) 2 私有开关
protected 0000 0000 0000 0100 (第 3 位) 4 受保护开关
static 0000 0000 0000 1000 (第 4 位) 8 静态开关
final 0000 0000 0001 0000 (第 5 位) 16 只读（不可变）开关

例子 A：public static 变量

  • 变量定义：public static int score;
  • JVM 检查发现：public 灯亮了（1），static 灯亮了（8）。
  • 最终返回的数字：$1 + 8 =$ 9。
  • 二进制状态：0000 0000 0000 1001

例子 B：private static final 变量

  • 变量定义：private static final String token;
  • JVM 检查发现：private 灯亮了（2），static 灯亮了（8），final 灯亮了（16）。
  • 最终返回的数字：$2 + 8 + 16 =$ 26。
  • 二进制状态：0000 0000 0001 1010

调用方法

Class类提供了以下几个方法来获取Method：

  • Method getMethod(name, Class...)：获取某个public的Method（包括父类）
  • Method getDeclaredMethod(name, Class...)：获取当前类的某个Method（不包括父类）
  • Method[] getMethods()：获取所有public的Method（包括父类）
  • Method[] getDeclaredMethods()：获取当前类的所有Method（不包括父类）

其实这个和我们上面提到的获取字段值是一个道理的

静态代理

核心定义：为目标对象提供一个代理对象，并由代理对象控制对目标对象的访问。代理对象可以在目标对象方法执行的前后，进行额外的增强处理，目标对象只需要专注于自己的核心业务逻辑即可。

生活中的通俗例子：

你想租房，不用自己挨个找房东看房、签合同，只需要找「房产中介」，中介就是你的代理，帮你处理租房的杂事，你只需要最终签约入住即可。
明星开演唱会，不用自己对接场地、票务、安保，只需要找「经纪人」，经纪人就是明星的代理，明星只需要专注于唱歌表演。
在这个逻辑里：你 / 明星 = 目标对象，中介 / 经纪人 = 代理对象，核心业务是「租房入住」「唱歌表演」，额外的增强逻辑是「找房源、签合同」「对接场地、处理票务」。

代理模式的核心价值总结：

✅ 解耦：目标对象和增强逻辑彻底分离，互不影响

✅ 增强：在不修改目标对象源码的前提下，对方法功能做扩展

✅ 复用：增强逻辑可以被多个目标对象复用，不用重复编写

静态代理的特点就是代理类是程序员手动编写的 编译器就确定好的类 一个目标类对应一个代理类 在代码编译之前，我们手动专门写一个「代理类」；这个代理类和被代理的目标类实现同一个接口，在不修改原有业务代码的前提下，给目标方法额外增加前置、后置附加逻辑（日志、参数校验、耗时统计、权限判断等）。

但是代理类存在很多缺点：

代码冗余严重：一个目标类对应一个代理类，如果项目中有 100 个业务类，就要写 100 个代理类，开发效率极低，维护成本爆炸。
扩展性极差：如果业务接口新增一个方法，所有的代理类都要同步修改，违反了开闭原则（对扩展开放，对修改关闭）。
耦合度高：代理类和目标类强绑定，代理类只能代理指定的目标类，增强逻辑无法灵活复用。

而动态代理就能很好地解决这些问题

学习了静态代理之后就来学习动态代理 动态代理主要依赖两个东西 一个代理类InvocationHandler一个中间类Proxy

其中Invocation就是我们实现增强的地方 而Proxy呢更多的可以把它理解成一个傀儡 当它被调用时 它会去找到InvocationHandler 然后InvocationHandler就来执行对应操作
